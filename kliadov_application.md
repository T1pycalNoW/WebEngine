1. Проблемное поле:

Веб-игры, создаваемые под площадки-дистрибутивы (Яндекс Игры, CrazyGames, VK Play…) требуют особой работы над оптимизацией игры и ее конечным весом, но специализированного движка, сфокусированного на качественных браузерных играх не существует. Зачастую возникают следующие проблемы:

1.1. Конечный вес игры: игра скачивается по сети, так что каждый МБ памяти влияет на скорость загрузки. Это делает иррациональным выкладывание тяжелых игр из-за того, что большинство игроков закроют вкладку еще до запуска игры.
1.2. Лимит памяти вкладки: браузер ограничивает размер кучи (~2-4 ГБ), переполнение моментально закрывает вкладку.
1.3. Сборщик мусора: выделение памяти требует большего контроля, чем на ПК, при паузе GC возникают фризы.
1.4. Батарея: на мобильных устройствах неправильная оптимизация садит батарею и перегревает телефон.

2. Заказчик и целевая аудитория:

Начинающие разработчики веб-игр под платформы-дистрибутивы, которым нужен легкий инструмент, позволяющий создавать легковесные игры. Инди-команды, которым нужен инструмент, дающий полный контроль над создаваемой игрой.

3. Аппаратные и программные требования:

ОС: Windows 10/11 x64.
GPU: любая видеокарта с драйвером, поддерживающим Direct3D 12 и Vulkan 1.1+.
CPU: любой x64 процессор
RAM: от 2 ГБ

4. Функциональные требования:

4.1. Окно редактора.
4.2. Создание примитивных объектов.
4.3. Добавление собственных моделей и текстур.
4.4. Перемещение объектов.
4.5. Управление светом.
4.6. Настройка шейдеров.
4.7. Перемещение камеры.
4.8. Постобработка кадра.
4.9. Веб-сборка игры.

5. Похожие или аналогичные продукты:

Unity: пустая сборка весит около 5-7 МБ, многопоточность С#-кода не поддерживается, рендер через WebGL - устаревший API.

Unreal Engine: официально не поддерживает веб-билды.

three.js: рендер-библиотека, нет игровой архитектуры (сцены), физики, пайплайна.

PlayCanvas: платный, основной workflow на сайте - требуется интернет для использования.

6. Инструменты разработки и базы данных

Языки: С++ 17, WGSL
Графический API: WebGPU (wgpu-native)
Веб-билд: Emscripten
Библиотеки: GLFW, GLM, stb_image, assimp
Среда: Visual Studio 2022
База данных: не требуется

8. Возможные риски:

8.1. Новизна API: WebGPU испытывает проблемы с Safari и Firefox.
8.2. Расхождение между реализациями WebGPU: Chrome, Firefox и Safari реализуют API по разному, т.е. работающий код в одном из браузеров может давать неправильный результат в другом.
8.3. Ограничения хостинга для поточности: не все бесплатные площадки предоставляют доступ к ней. 
8.4. Неизвестное железо пользователя: игроки могут использовать как слабые телефоны, так и хорошие компьютеры.
